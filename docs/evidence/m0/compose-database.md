# M0 Compose and database checks

## Compose services

`bash infra/verify-dev-compose.sh` exited 0 on the temporary Docker runtime with Docker Compose 5.7.0.

The same check exited 0 on Mahdi's Docker Desktop after switching to `desktop-linux`. The installed Engine was 29.9.2 and Compose was 5.6.1. All three services became healthy on the pinned images. The temporary VM was stopped without removing its volume.

| Service | Observed |
|---|---|
| PostgreSQL | TCP at `127.0.0.1:5432`, server 18.6, PostGIS 3.7.0, separate `zaafran_test` database |
| Martin | Healthy on loopback, TileJSON 3.0.0, 29-byte vector tile at 0/0/0 |
| OSRM | Healthy on loopback, Algiers route 873.8 m in 90.2 s |

The synthetic PMTiles archive and clipped road fixture regenerated byte for byte. Osmium reported 13,102 ways and zero missing node references. See the road fixture's license and provenance in `infra/fixtures/algiers-roads.LICENSE`.

## PostgreSQL integration

`pnpm test:int` ran the two database integration files with 5 passing tests against the real Compose PostgreSQL server. Polling `pg_database` during the run observed one migrated template and two separate file clones. The names were absent after teardown.

The database package passed strict typecheck, lint, format and build. Its 16 unit tests passed. On a disposable PostgreSQL container, the root `pnpm db:migrate`, `pnpm db:seed`, and `pnpm db:reset --confirm` wrappers exited 0. A probe table was removed by reset and all three extensions were restored.
