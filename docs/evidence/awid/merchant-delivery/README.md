# Merchant delivery settings

The production-browser test opens the screen as an authenticated owner and writes the mode, radius and fee to PostGIS. A second write advances the revision. The stale browser gets a conflict, focuses Reload, and then shows the saved fee and the newer prep time. Four Arabic/French, light/dark, phone/desktop captures passed axe WCAG A and AA and the overflow check.

Round one had a subdued heading, excess space below the mobile header, competing section titles, mismatched field widths and a three-column layout that orphaned an input. Round two tightened the header, used two columns, aligned the money and duration inputs and kept both card titles at the same size. The sticky save bar overlapped fields on phones, so the final round placed the full-width action below the form.

Run `pnpm exec playwright test --config e2e/auth.config.ts auth-merchant-delivery.spec.ts` after building the web app and API and starting PostGIS. The AWID shell and gallery registration follow during the Lane B design integration.
